# 4inOne Specification V2 — Changelog

This revision updates the earlier blueprint to the current product direction.

## Added or clarified

- Public product explanation before registration.
- Optional demo workspace with clearly labelled example data.
- Strict separation between demo data and real user data.
- Real accounts should use helpful empty states instead of fake records.
- Short onboarding with personal/shared use and preferred starting areas.
- Global, permission-aware search across domains.
- Profile and settings structure.
- Current icon strategy: mostly normal UI icons; 3D/illustration used selectively.
- Connection Engine V1 deliberately precedes Suggestions and Automations.
- Connections never grant permissions.
- Current implementation order: finish all four domains before Connection Engine V1.
- Optional future local/private AI direction, without making AI a product requirement.
- Clearer competitive positioning against family organizers, calendar apps and task managers.

## Changed

- Reisen is completed before Connection Engine V1 in the recommended product build sequence.
- The roadmap now prioritizes stabilizing existing functionality and end-to-end testing before cross-domain intelligence.
- Design guidance is more mature and less dependent on 3D illustration.
- Demo functionality is treated as a sandbox/experience, not seeded user content.

## Unchanged core idea

> Every area works independently. Connections add value only where real-life things genuinely belong together.
